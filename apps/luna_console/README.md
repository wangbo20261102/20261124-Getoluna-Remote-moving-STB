# Gento Luna 协作搬运控制台

独立 Windows 原生窗口，直接通过现有 SSH 配置与 Apex 后端管理机器人，不需要打开 Apex 或 FXPlatform，也不另建 SDK 会话。使用现有 Python/Tk；图像依赖 Pillow 独立放在本控制台 vendor 目录，不改系统 Python 软件包。密码不写入文件、不进入日志。

## 入口与操作

双击桌面 **Gento Luna 协作搬运控制台**。界面自动只读刷新状态、参数和摄像头预览，不会自动使能、Home、启动遥操或动作夹爪。

1. **读取状态 / 只读预检**：先检查两块电池、故障、关节反馈、J6、SDK 和模块状态。
2. **连接 PICO USB**：复用本机原 USB 网络/反馈准备程序，头显上的首次 USB/VPN 授权仍由操作者完成。
3. 确认空载/物体已放稳、双腕支撑且手柄松开，再勾选确认。
4. **一键就绪（阻抗）**：启动 Robot、set ready，必要时依次位置→阻抗；不执行 Home、不启动遥操。可用“仅连接 Robot”只检查运行参数。
5. **启动 PICO 遥操**：在阻抗保持状态启动 Tool/Teleop；底盘桥随 Teleop 启动。PICO 连接 6.6.7.100，摇杆先回中、侧握/扳机先松开。若新会话需要 Home 门控，须单独确认并点击 HOME。
6. **暂停遥操**：停止输入模块，保留 Robot 当前模式、摄像头和 MAXHUB。软件暂停不等同于实体急停。

**HOME** 单独确认后才下发。**仅清故障**调用 clear_fault，不调用会归位的 legacy reset。**待机/断开 Robot**可能使无抱闸腕部失去保持，必须有稳固支撑。

## 参数与画面

“所有参数”可搜索、查看原始文件和哈希，分开显示保存值与 Robot/VR 接收器运行值。未启动模块标为“仅保存值”，不显示假定的当前值。覆盖工具动力学、阻抗、PICO 缩放、Home 校正、QP/IK/碰撞、相机、动画和服务定义。没有公开回读接口的厂家固件内部项目不伪造为已读回。

关节页显示当前角度、速度、力矩和模型限位；J6 ±60°为此前厂家控制器读取记录，模型限位与完整固件限位不混淆。过期反馈显示未知。参数页只读，不重写厂家限位、负载、保护阈值或现有缩放设置。

视频直接订阅当前压缩图像，不抢占 PICO WebRTC 房间，不额外打开摄像头。桌面检查预览约 2 帧/秒，原摄像头采集配置和 MAXHUB 显示保持不变；过期画面有明确标识。

## 文件

- 本机：`apps/luna_console/`；本机日志在该目录 `logs/`。
- 机器人：`/home/nvidia/luna-test-runs/20261125-unified-console/robot_agent.py`；动作审计 `actions.jsonl`。
- `install.ps1` 上传同版代理、语法检查并创建快捷方式；不启动 Robot/Teleop/Tool。
- `python app.py --offline` 仅展示布局，设备操作禁用。
- `test_agent_guards.py` 的执行接口全部 mock，不发实机命令。

关闭窗口仅关闭本窗口的 SSH/视频订阅；不会停用机器人或 MAXHUB。所有运动相关功能由现场操作者点击；交付验证不以自动搬运或自动 Home 试验替代现场确认。
